## Current architecture references

Read [docs/architecture.md](docs/architecture.md) for the process/data-ownership model and [docs/operations.md](docs/operations.md) for setup, maintenance and recovery. The activated shared service is the sole production Library owner; clients use authenticated HTTP. Never repair a service outage by constructing Library in a client or deleting the activation marker. Active clients and wrappers are Go/HTTP-only and fail closed without a service. Default builds and tests must work from a fresh checkout.

## Current relationship architecture
People, Teams and Projects are entities stored in entities, with entity_relationships for member_of, works_on, belongs_to and related_to. The old typed-tag API and IDs are compatibility adapters for existing imports; triggers keep the relationship store synchronized. UI tags are topics/types only, and redundant identity/type chips are hidden.
Confirmed authorship remains item_authors; confirmed attendance remains meeting_people. Never infer either from a generic person connection: preserve legacy mentions as Related people. Entity profiles never connect to themselves. Trash hides an entity and its visible links without destroying history; only explicit restore brings it back. Use create_entity/list_entities/get_entity/link_entity for organization, set_authors for authors, and link_meeting_people for participants. Teams expose membership and connected records; People show a deduplicated Owned / Authored list, then explicit Mentioned in documents and Meetings; the underlying ownership, authorship, creator and mention records stay distinct. Older rules below describing person/project/team tags apply only to compatibility inputs.
Do not remove legacy IDs or adapters until every connected client has migrated. All mutations, migration and compatibility triggers are owned by Library.

# Atlas project

Atlas is a local macOS knowledge browser. Build within this project; do not modify external source folders.
Preserve original sources locally. Do not publish or send private work content to external services without explicit authorization.
All app, MCP, and automation mutations use the activated service Library API: the Go implementation lives in `service/internal/library/`. Preserve manual organization during summary updates; clients never open production SQLite.
Slack status items require explicit source-channel identity and date bounds; do not generate unsupported claims about Slack activity.
Use native Mac packaging with the browser interface inside WKWebView. Keep library data out of the app bundle and do not remove it during builds.
Run `python3 -m unittest discover -s tests` and `zsh build.sh` for relevant changes. Avoid new dependencies when the standard library is sufficient.

## Documents and project membership

Store each document once with kind=document. Documents view automatically includes documents and reference material; do not create a second copy for a project. Supply projects=[canonical project names] or project-category tags during import. Documents without a project remain in Documents; use topic tags such as Strategy or Architecture for broad material. A document can belong to multiple projects.
For a Google Doc snapshot, provide its canonical URL in doc_urls; the library uses its Google document ID to avoid duplicate records and adds newly requested project memberships without overwriting summaries or manual tags. Do not assume project membership from a passing mention: use supplied context or explicit source evidence. Existing project summaries that describe a Google Doc are summaries, not fresh document fetches; preserve that provenance.
Project overview items use kind=project and their canonical name as a project tag. The project’s Documents, Meetings, and Updates sections derive from that membership. Summary edits preserve membership; tag changes immediately affect project views.

## People, stars, and document dates
Supply authors=[canonical person names] only with explicit authorship evidence. Reviewers, attendees and mentioned people are not authors. Person pages automatically list documents using this relation; no duplicate summaries are needed. Use set_authors to correct authorship. Preserve manual stars during ingestion and summary updates. Documents without a source date display the original Atlas added date with date_basis=added; do not invent creation dates. A supplied source date retains date_basis=source. General lists place stars first, but recurring meeting and feed histories always stay newest first.

All item types now have a visible sortable date. When no date is supplied, use a clearly labeled source date if available, otherwise the original Atlas added day in America/Los_Angeles. Do not extract deadlines or incidental body dates. Date edits use set_date with a revision and preserve created; date_basis records source, added, or manual.

Google Doc links are normalized to https://docs.google.com/document/d/<ID>/edit. Preserve resourcekey access parameters; remove account routing, tracking parameters, and fragments. Deduplicate by document ID. Keep original source snapshots immutable; only summaries, metadata, and derived source links are normalized. Published /document/d/e/... links remain unchanged.

Project summaries link to cached document entries with [[document title]], not direct Google Doc action links. Keep document descriptions in the document’s own summary; project Documents sections automatically show Blurb, Notable detail, and source metadata when supplied. The reader title is plain text; the Open original Google Doc button opens Google Docs. Avoid duplicating a Documents section in project overview Markdown.

Projects and People show documents in a separate compact right-hand column: linked titles, stars, and a separate ↗ source link for Google documents, starred first, with no sorting controls. Clicking a document in a person/project/team column loads it in the center while retaining the originating collection on the right and its left-list selection. Highlight the preview document, name the retained collection, offer a return-to-profile link and an explicit Open in Documents action for the connections/tagging rail. Back/Forward restore the preview context and scroll. Candidate/interview navigation remains separate. Keep project/person summaries in the main reader, with no embedded document cards. Other document collections keep the linked-title and quick-blurb presentation. General result lists use the document Blurb or Summary paragraph as their preview. Document list titles open cached Atlas entries; the Open original Google Doc button and the compact column’s ↗ source link open the original Google Doc.


## Google document refresh
A Refresh requested checkbox is a persistent queue flag, separate from Inbox review state. Hourly runs use list_google_documents(mode=dirty). Daily 6 a.m. runs search Google Drive metadata for native Docs created or modified within the last 30 days and intersect file IDs with Atlas. Do not individually poll dormant documents; old documents edited again can reenter through the metadata search. Recent means Google source timestamps, not the Atlas added date or a date mentioned in the body.
Use check_document_source before fetching content, inspect_document_content before generating a summary, and refresh_document for the commit. Never use import_item to replace a document. Only complete, verified source reads may clear a request. Missing access, truncated content, failed writes or revision conflicts leave pending requests intact. Re-read metadata after fetching content; if the source changed mid-read, retry without committing inconsistent data.
Refreshes preserve manual tags, stars, authors, dates and project membership, retain previous source snapshots and summary revisions, and return changed content to their existing views (internal review bookkeeping remains compatible). Status in the summary must be supported by the newly fetched source; absence of an explicit status means unknown, not completed. Metadata-only changes do not require new AI summaries. The local scripts/atlas_tool.py helper is an API fallback when an existing MCP connection lacks the new tool definitions; it routes all writes through Library.


Document reader actions use Remove, not Delete: this removes the Atlas entry to recoverable Trash and cleans its local links, without deleting the original Google Doc. Document projects, authors and tags appear below the action row; keep membership/author navigation and tag removal available there. Inbox navigation and reviewed/unreviewed controls are not shown in the UI. Imported and refreshed items appear in their relevant existing views. Keep internal Inbox bookkeeping and the compatible MCP review API for existing imports and refresh workflows; do not confuse it with source document status.

Feeds and recurring meetings open their latest full entry and use the right-hand column for newest-first dates; all editions/sessions keep that date column when selected. Documents opened in Documents view use the right column for all available tags, grouped by category, with checkboxes to apply/remove membership and a New tag action that creates and applies a tag. Main reader project/author context remains available; avoid duplicating a full tag list there. Back/Forward navigation includes dated entry changes.

## Interview candidates
For interview imports pass candidates=[canonical candidate names]. Library creates or reuses candidate profiles, applies candidate person membership and an Interview type tag, and preserves each session once. Interviews collects Interview-tagged/native interview records and candidate profiles; Meetings excludes interviews. People and its sidebar tags exclude profiles marked Interview Candidate or sourced as interview-person. Candidate profiles retain their linked interviews in the right-hand column; colleague People pages show authored Documents. Interview documents remain in Documents. These are browse collections, not duplicate imports or destructive moves. Speakers and candidates are never inferred as document authors. For existing sessions use link_interview; it preserves transcripts, summaries, dates, stars and manual tags. Reuse canonical identities, do not recreate people in Trash, and retain identity uncertainty rather than inventing aliases or hiring status. Interview roundups can link to the same candidate profile.

## Persistent schedule definitions
After creating, updating, pausing or deleting an Atlas automation, export the registered definitions with scripts/export_schedules.py and keep schedules/manifest.json and the per-task Markdown prompts current. These are portable documentation, not a replacement for registration through the desktop automation tools. Bind recreated jobs to new destination chat IDs and expand path parameters. Chrome imports use scripts/chrome_documents.py, read only the configured latest unencrypted session, submit every eligible source to Library.submit_sources; Atlas owns deduplication, pending work and tombstones. Process only Atlas-selected pending sources through complete_intake, fetching Google sources read-only.

Chrome automatic imports require a nonblank title that does not contain Untitled document, ignoring case and repeated whitespace. Filter browser snapshot titles and recheck initial/post-read Google metadata titles. Never invent a title to bypass the rule; skip drafts quietly. Atlas Trash IDs remain excluded even if their source is later renamed.

Weekly updates navigation is hidden; existing status-update records and APIs remain available. Interview import tools retain their person-profile storage for compatibility, while the UI presents candidate profiles under Interviews. Do not infer a colleague is a candidate merely because they interviewed someone.

## Activity history
Record meaningful successful additions/content changes in Library activity_events inside the write transaction. Keep duplicate imports, empty checks and unchanged Google metadata checks out of the panel. Reconstruct historical additions only from saved created timestamps, explicitly marked historical; never invent prior refresh activity. Activity has its own sidebar entry after Feeds and before Trash, fills the workspace only when selected, supports older pages, and preserves scroll position during background updates. Keep it hidden in other views. All callers share this persistent library log; scheduled jobs do not append separate success entries.

Activity content fingerprints reconcile older connector changes when read, labeling the observed change Content updated rather than inventing its cause. Ignore unchanged content despite changed revision/check metadata, tags or stars.

## Central intake and tombstones
Chrome and Zoom schedules are collectors: run scripts/collect_sources.py and submit every eligible source. Never implement seen lists or duplicate/Trash decisions in schedule prompts. Library owns persistent source_intake and source_tombstones, including canonical Google IDs, Zoom keys/hashes and conservative legacy transcript matching. Ambiguous matches require review instead of a second import. complete_intake rechecks identity and tombstones under the shared writer lock, preserves queued full Zoom text, requires its expected source hash, and records successful writes in Activity. Automatic imports never set explicit=true. A direct human re-add uses import_item(explicit=true), restoring the matching removed record without overwriting manual content/organization; use the local helper if connected tools lack the explicit flag. The manual Add material UI is explicit. Restore clears that item's tombstones; source deletion remains local to Atlas. Existing Trash is synchronized into tombstones.

## Original sources and references
Keep the reader title plain text and an explicit Open original Google Doc action near it. Distinguish primary sources from URLs mentioned in saved content; references are not automatically summary sources. Show secondary documents and calendars in collapsed Referenced documents/Referenced meetings sections with labels and dates recovered from preserved text. Prefer unambiguous cached document titles and link them to Atlas summaries, with a separate Google ↗ action. Never invent unknown titles/dates or fetch external resources just to render references. Promote a Calendar action only for an explicitly associated meeting source. Preserve source snapshots.

## Meeting participants and People
Confirmed work meeting participants create/reuse colleague People through link_meeting_people, separately from authors and interview candidates. People profiles list linked Meetings plus authored Documents. New Zoom intake can use unambiguous full-name speaker labels; exclude the configured library owner, guests and device labels. Calendar is read-only corroboration when needed: match date, actual transcript timing, title and speakers, read full event details; invitees alone are not confirmed attendees. Do not derive names solely from email addresses, recreate people in Trash, or rewrite meeting summaries/transcripts during linking.

Full-text search matches titles, summaries and preserved text using all query words as prefixes. Put complete title matches first, then partial title matches, then content-only matches; retain selected sorting and stars within each tier. Show a plain escaped matching excerpt for content matches instead of an unrelated blurb.

Quoted search phrases require adjacent words in order; unquoted words retain prefix matching. The UI must preserve search_title_rank ahead of date/title/star ordering, so it cannot undo Library ranking.

The UI defaults to Title / name search, with an adjacent Full text selector. Carry search_scope through requests and navigation history. Title mode searches indexed titles and meeting-series names only; Full text includes summaries and complete sources. Quoted phrases work in both modes. Library/MCP calls retain full_text by default for compatibility.

Meeting session actions say View meeting history and focus the date rail, preserving the current session and reader scroll. Do not reopen the latest session for this action; ignore history responses if navigation changed while loading.

Confirmed non-interview one-on-ones group automatically when link_meeting_people runs. one_on_one_series maps the colleague People ID to a series, with the configured library owner implicit. Preserve existing cadence, never merge colleagues by first name alone, and leave ambiguous participants/series for review. backfill_one_on_one_series repairs existing sessions through Library.

Saved source snapshots are available as View saved original inside the reader's More… disclosure. More… always contains Remove… and optionally View saved original; keep the edit/summary toggle and live-source actions visible. Close the disclosure after selection, outside click or Escape.


## Starred source updates and lightweight browsing
What's changed shows only source-content updates detected while document/reference records are starred. Do not backfill unverified historical changes, count imports, metadata-only refreshes, summary edits, tags, or star changes as source updates. Group updates by document, newest first, preserving durable seen cursors; opening a result acknowledges only the change version that was displayed. Updates arrive when Atlas refreshes the source, not directly from Google push notifications. Keep this focused view separate from general Activity.
Listing/search hydrate lightweight database records, with no Markdown file reads or expansion of full source references. External summary files are checked on background /api/changes polling; read files only when their mtime/size changes, and index actual changes. Search-input and scope changes fetch only result rows, reusing catalog data and leaving Activity/sidebar untouched.

The reader has one Edit summary/Summary toggle, retaining unsaved drafts when switching to preview or saved original. Saving remains explicit. More… always contains Remove… and optionally View saved original; removal still uses the existing recoverable Trash confirmation flow.


Document owners, explicitly supplied creators and source-mentioned people are separate document_people roles, with evidence and optional stable email identity. Google ownership comes only from observed source.owners metadata or individual source.permissions entries with role=owner, never a byline, manager, last editor or assumed creator. Complete intake creates/reuses profiles and reports unresolved/Trash identities, caches missing ownership, and does not add network calls. People pages combine owned/created and authored documents in Owned / Authored, with role badges when roles overlap; Mentioned in remains a separate evidence-backed list. Named mentions never imply authorship or attendance. Keep candidates in Interviews and never recreate a trashed person.

Missing Google owners are reconciled by the existing hourly refresh schedule using Library.list_ownership_lookups (maximum three) and record_ownership_lookup. Durable per-document and connector cooldowns back off 6 hours, 1 day, 3 days, then weekly. No extra Google calls while paused; reuse metadata already fetched for dirty documents. Owner-only repairs never fetch content or clear refresh flags. Missing provider metadata can be recorded with error and provider_unavailable=true without fabricating MIME/trash/owner fields. Keep owners distinct from confirmed authors and creators. Export registered schedule updates.

Google metadata requests for ownership use fields="*"; this connector exposes owners through permissions. Ignore non-user, deleted, writer, organizer and pending-owner entries. Missing owner permissions never imply no individual owner. Owner-only repair may use positive permission metadata even when trash state is omitted, preserving that uncertainty; reject explicitly trashed sources. Content intake and refresh retain their trash verification requirements.

Keep README.md and schedules/README.md aligned with current behavior when changing import, refresh, ownership, relationships or UI flows. Full registered schedule prompts and manifest must be re-exported after automation changes; include the hourly owner repair pass and current metadata permissions fallback in schedule documentation.

The right-hand context rail stays mounted across reader updates. Do not hide/clear it at the start of openItem or replace its live innerHTML during refresh. Reconcile changed nodes by stable identity, skip unchanged markup, retain focus and same-context scroll, and hide only when closing the reader or showing an item without a rail. Apply this to document connections/tags, entity documents and meeting/feed histories.

People context rails combine owned, created and authored documents under Owned / Authored, deduplicated by item ID, then Mentioned in (explicit source mentions), then Meetings. Keep the underlying ownership, creator, authorship and mention records distinct; mentions can overlap ownership/authorship.

## Shared service architecture
One Go service process, supervised by the signed native helper in `dist/Atlas.app` under the installed launchd job label, owns the production Library, SQLite connection and file mutations. Serve UI/API plus stateless Streamable HTTP MCP at authenticated loopback `/mcp`. All application requests serialize around the single SQLite owner connection. The native window, MCP clients, collectors and helpers connect through the service; never instantiate Library in production client scripts. The active client boundary is authenticated HTTP. Use scripts/service.py status/start/stop/restart for the active Go job; install/request-access target signed Go apps; install requires explicit owner/timezone. Go upgrades require deliberate signed candidate deployment following service/DEPLOYMENT.md. The signed native helper handles ordinary macOS consent and supervises Go; do not run a second raw backend from launchd. Active clients never fall back to local database access, including before activation. Keep service tokens private; never log or publish connection.json or credential-bearing URLs. Restart the service after backend updates; restarting Atlas alone does not reload the backend.

People-column meeting links use the same contextual preview as documents: preserve the left profile selection, owner collection and scroll, highlight the selected meeting, and offer Open in Meetings. Navigation history retains preview type as well as context. Meeting previews do not replace the profile rail with meeting dates; full Meetings view exposes meeting history. Background updates refresh the retained owner collection for either preview type.

Builds sign Atlas and AtlasService inside-out with the reusable Keychain identity Atlas Local Development (or explicit ATLAS_SIGNING_IDENTITY), then verify signatures. Never silently revert to ad-hoc signing. Keep signing keys outside the repository and leave certificate trust/key authorization changes to the user. Permission persistence must be checked across a rebuild rather than assumed.

## Validation and deployment boundary

Current validation status is documented in service/STATUS.md. Candidate validation uses only marked disposable test libraries; never point an experimental owner at the live root. Code acceptance or a merge does not authorize production replacement or lifecycle changes; follow service/DEPLOYMENT.md and current user authorization. Never run two owners or bypass a service outage with direct database clients. Application behavior is accepted through the HTTP/MCP contract suite; direct SQLite infrastructure tests are supporting evidence only.

Build/runtime code belongs in service/ with pinned module checksums. Library operations belong in the Go service; clients and collectors use its API. Preserve wire contracts, schema/files, legacy IDs, tombstones, history and manual metadata. Requests remain serialized and Store.Lock is outer-operation-only/non-reentrant; domain helpers must not recursively acquire it. Go unit/transport/race checks supplement endpoint acceptance, not replace it. Keep generated binaries, fixtures and reports in ignored service/.work/.


Google document mentions require explicit structured Google Docs people chips or single-address mailto links, never plain names in prose. Read get_document with all tabs and table content. Pass role=mentioned with observed email plus person_chip={personId,personProperties:{name,email}} or person_link=<observed mailto URL>. The Go API rejects unstructured mentions; email is primary identity. Do not infer unknown names from email, recreate People in Trash or auto-remove historical links. Owner/creator/author roles and Zoom attendance remain separate.
