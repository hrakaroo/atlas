The hourly job is the normal owner of this workflow.

Maintain Google documents in the private local Atlas library at ${ATLAS_ROOT}. Use the connected Google Drive account for read-only source access and Atlas tools for local writes. Never edit Google Docs, publish private content, or import duplicate Atlas items.

For every selected Atlas document:
1. Read its current Atlas item and revision. Fetch Google Drive metadata using get_file_metadata(fileId=...,fields="*",supportsAllDrives=true); preserve observed identity, timestamps, MIME type, trash state, permissions and owners. Pass observed permissions to Atlas for individual role=owner linking; do not infer authorship. The connector may return snake_case fields and may omit version; map the observed values without inventing a version. Do not refresh trashed, inaccessible or non-native-Doc sources; report the issue and retain any refresh request.
2. Call check_document_source with item_id, expected_revision and source={file_id,title,created_time,modified_time,version if available,permissions/owners only if returned}. If needs_content=false, do not fetch or summarize the document.
3. If content is needed, use Google Drive get_document with no fields restriction to read complete structured content for all tabs. Build deterministic plain text from all tab titles and body text in document order, including table text; exclude metadata, indexes and wrapper messages. Do not treat incomplete, truncated or missing content as a successful read. Re-read metadata after the content read. If modification time or available version changed during the read, retry with a consistent snapshot, at most twice; otherwise report and retain the request.
4. Call inspect_document_content with the complete original_text. If content_changed=false, do not generate a summary; call refresh_document with the complete source text and metadata and the current expected_revision, omitting summary. If content_changed=true, get the current item and generate an updated Markdown summary in its established format, including its quick Blurb, notable detail and explicit document status when present. Summarize only supported facts; an absent status is unknown, not completed. Preserve relevant internal links and user-authored context rather than dropping them casually. Call refresh_document with original_text, source, summary and expected_revision. A changed revision means another writer intervened: re-read, compare and regenerate against the current item before retrying; never blindly overwrite.
5. Verify the returned item or get_item: the refresh flag must be false, source modification metadata must match, and organization must remain intact. Do not use set_refresh_requested(false) to acknowledge work independently of a successful refresh. Failed documents stay queued. Do not use import_item or update_summary as substitutes for refresh_document.

STRUCTURED DOCUMENT PEOPLE (supersedes name extraction or flattened document reads)
Read get_document (omit fields to obtain the complete resource) instead of get_document_text. Traverse every returned tab in document order, recursively including child tabs, paragraphs and table cells; accept the connector's flattened tab body or the native documentTab.body shape. Do not duplicate a legacy top-level body when tabs contain it. Build complete deterministic original_text from tab titles and document content: textRun.content verbatim, people-chip displayed name (or email when no name), and rich-link title plus URI. Keep table text in row/cell order. Include header/footer/footnote text when returned. Exclude API metadata, index numbers and wrapper messages. Do not treat a truncated, missing or incomplete resource as a successful read. Extract mention identities separately from this same structured response; never identify a person from the flattened text.

Document mentions are structured identities only. A typed name, an @-prefixed text run, a byline, an inferred email, or a generic profile URL is not a mention identity. Traverse all returned tab bodies and nested table/paragraph elements, plus headers/footers/footnotes when present, for paragraph elements with person={personId,personProperties:{name,email}}. For each actual people chip, pass document_people entries {name:<observed name if available>,email:<observed email>,role:"mentioned",person_chip:{personId:<observed ID>,personProperties:{name:<observed name if available>,email:<observed email>}}}. An ordinary textRun link is eligible only when textStyle.link.url is a single-address mailto: link; pass {name:<explicit linked display name if present>,email:<exact linked address>,role:"mentioned",person_link:<observed mailto URL>}. Never fabricate chip IDs, emails, names or link targets; omit unknown identity fields rather than deriving names from email local parts. Use email as identity, deduplicate repeated chips/links by email, and reuse canonical People names only when the email matches. If a chip has no name, Go may link an existing email identity but must not guess a new full name. Conflicting identities and People in Trash remain unresolved; do not recreate them. Other profile URLs are unsupported and must not be guessed. If structural metadata is unavailable, omit mention links and report the limitation; do not fall back to name recognition. Owners/creators from verified Google metadata and explicitly supported authors remain separate roles.

After a successful verified refresh, use the structured identities from that consistent snapshot with link_document_people(item_id=...,people=[...]) to add verified mentions and check get_item/get_person. This is a separate organization update: do not rewrite summaries, clear refresh requests independently, replace_roles=["mentioned"], or remove existing links merely because a chip is absent. Report an unresolved organization update without claiming it succeeded. Metadata-only/no-content checks and owner-only repairs do not download a document to look for mentions.
